# Детекция ботов по событиям cookie

Модель ранжирует куки по вероятности того, что это трафик сервисов автоматизированного сбора данных. <br>
Метрика: Precision при Recall >= 0.7.

Решение: CatBoost на признаках, собранных по событиям куки внутри её окна наблюдения. Качество оценивается кросс-валидацией по времени.

Итог на скрытом тесте: P@R0.7 = **0.752**<br>
На CV (5 временных фолдов): P@R0.7 = 0.721 ± 0.077, PR-AUC = 0.762 ± 0.026.

## Как запустить

1. Python 3.12.
2. Установить зависимости: `pip install -r requirements.txt`.
3. Положить в `data/` файлы `train.csv`, `test.csv`, `events.csv.gz`.
4. Открыть `train.ipynb` и выполнить Run All. Прогон занимает около 10 минут, в основном из-за Random Search. <br>
Результат `submissions/submission.csv`.

`eda.ipynb` для сабмита не нужен, он выполняется примерно за полминуты.

`random_seed` везде зафиксирован, поэтому результат всегда одинаковый. Обучение идет на CPU.

## Данные и очистка

- Признаки считаются только по событиям внутри окна `[window_start_ts, window_end_ts)`.
- Событий `captcha_shown` находятся после окна и, вероятно, это уже срабатывание антибота. 
- Полные дубли (2 954 события, 1.5%) случайны по таргету и удаляются. Разные события в одну секунду - настоящие, они остаются.
- В пределах одной куки `platform` пишется в разном регистре (`web`/`WEB`/`desktop`). Приводим к `desktop`, `android`, `ios`.

Подробности в `eda.ipynb`

## Признаки

Одна строка на куку, `src/feature_generation.py`.

| группа | признаки | идея |
|---|---|---|
| User-Agent и платформа | `platform`, `ua_kind`, `ua_os`, `ua_browser`, `ua_device`, `n_ua*` | тип клиента |
| поиск | `max_page`, `mean_page` | боты листают выдачу глубже |
| курсор | `ptr_std_*`, `ptr_mean_*`, `ptr_range_*`, `n_pointer_points` | у ботов курсор держится в узкой области или отсутствует на desktop |
| разнообразие | `n_item_id`, `ratio_loc`, `ratio_cat` | боты смотрят больше объявлений, но в меньшем числе категорий |
| объём и воронка | `n_events`, `ratio_ev_*` | доли типов событий: фото, избранное, контакты |
| темп | `dt_median`, `dt_min`, `dt_std`, `dt_max`, `dt_cv` | интервалы между событиями |
| возраст куки | `cookie_age_days` | у ботов куки моложе |

Пропуски (`NaN`) не заполняются: CatBoost обрабатывает их сам.

Медианы признаков у ботов и людей - в конце `eda.ipynb`. Вклад признаков в модель на новых данных - permutation importance в `train.ipynb`.

## Валидация

Тест идёт позже train по времени, поэтому вся валидация тоже по времени:
- holdout - последние дни train (около 24% кук). На нём смотрим качество базовой модели, сравнение с Dummy, bootstrap-интервал, важность признаков и разбор ошибок
- **`TimeSeriesSplit(5)`** - на нём сравниваются конфигурации и выбирается финальная.

Метрики: P@R0.7 (официальная, `src/metric.py`) и PR-AUC. 

## Модель

- Базовая конфигурация: CatBoost, `depth=5`, `learning_rate=0.03`, 500 итераций, без ранней остановки.
- **Random Search:** 40 конфигураций, каждая оценивается средним по 5 фолдам, лучшая выбирается по P@R0.7.
- **Финальная модель:** лучшая конфигурация обучается на всём train. <br> Параметры: `depth=7`, `iterations=1200`, `learning_rate=0.036`, `l2_leaf_reg=16.1`, `random_strength=1.15`, `rsm=0.62`, `subsample=0.64`, без весов классов.

## Результаты

| модель | валидация | P@R0.7 | PR-AUC |
|---|---|---|---|
| Dummy (константа) | holdout | 0.082 | 0.082 |
| базовая CatBoost | holdout | 0.748 [95% bootstrap: 0.601–0.840] | 0.762 |
| базовая CatBoost | CV, 5 фолдов | 0.659 ± 0.067 | 0.755 ± 0.020 |
| лучшая из Random Search | CV, 5 фолдов | 0.721 ± 0.077 | 0.762 ± 0.026 |

± - стандартное отклонение по фолдам.

На скрытом тесте на stepik:

| сабмит | P@R0.7 |
|---|---|
| константный ответ | 0.094 |
| ранняя базовая модель: обучение на части train с ранней остановкой по holdout, меньше признаков | 0.684 |
| **финальная:** все признаки, лучшая конфигурация Random Search, обучение на всём train | **0.752** |
| финальная без 15 наименее важных признаков | 0.719 |



## Что пробовали и выводы

- **Метрика ранней остановки.** F1 при пороге 0.5 останавливал обучение слишком рано. PRAUC и P@R0.7 работали лучше, но ранняя остановка по тому же holdout завышала оценку. Итог: фиксированное число итераций и CV. Таблица в `train.ipynb`, раздел "Ранние эксперименты".
- **Гиперпараметры.** По P@R0.7 лучшая конфигурация заметно выше базовой (0.721 против 0.659). По более стабильному PR-AUC разница небольшая (0.762 против 0.755). К тому же оценка лучшей из 40 конфигураций на тех же фолдах немного оптимистична. Основной прирост дали признаки.
- **Веса классов** (`auto_class_weights="Balanced"`) явного выигрыша не дают: лучшая конфигурация без весов, а в топ-10 Random Search есть варианты и с весами, и без.
- **User-Agent.** Около 78% кук с Python-клиентами в UA размечены как люди, что странно. Поскольку неизвестно как именно получена разметка, было принято решение оставить как и есть и просто отметить этот факт.
- **Отбор признаков.** Если убрать 15 наименее важных признаков (в основном UA-признаки, часть курсорных и долей событий; список в `train.ipynb`, ячейка с `drop_features`), модель становится проще, но P@R0.7 на тесте падает с 0.752 до 0.719. Поэтому в финальной модели оставлены все признаки.

## Ограничения модели

- 78% кук с Python-клиентами в UA размечены как люди. Если разметка неточна, модель наследует эти ошибки.
- Куки с 1-2 событиями тяжело классифицировать, так как мало информации.
